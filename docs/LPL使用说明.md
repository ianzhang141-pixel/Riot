# 比赛研究台：从启动到查看比赛

目前你提供的是 Riot Developer Portal。先用它验证普通对局处理流程；职业 LPL 必须另行核验数据来源。你不需要在聊天、GitHub 或截图中公开 API Key。

## 1. 准备 Python 与代码

1. 在 Mac 按 `Command + 空格`，输入「终端」，按回车。
2. 输入 `python3 --version`，按回车。如果显示 Python 3.10 或更高版本，继续；如果提示找不到命令，或版本低于 3.10，请到 <https://www.python.org/downloads/macos/> 下载官方安装包，双击后按安装器提示完成，关闭并重新打开终端，再检查一次版本。不需要安装其他 Python 包。
3. 在 GitHub 的 Riot 仓库中打开包含本次更新的分支，点击绿色 `Code` → `Download ZIP`。解压得到的文件夹中，应直接有 `lolab`、`README.md` 和 `tests`。**不要打开文件夹里的旧 `lol_decision_lab_v0_1_riot_api.zip`；那是另一个历史项目。**
4. 在终端输入 `cd `（字母后有一个空格，先不要按回车），把刚解压的整个文件夹从 Finder 拖进终端，再按回车。
5. 输入 `python3 -m lolab serve`，按回车。看到「控制台已启动」就成功。终端保持开着。
6. 在浏览器地址栏输入 `http://127.0.0.1:8010/research`，按回车。停止服务时回到终端按 `Control + C`，下次使用重复第 4、5 步。

如果显示端口被占用，可以用 `python3 -m lolab serve --port 8012`，浏览器地址也改成 `http://127.0.0.1:8012/research`。原来运行中的旧服务不会自动加载新代码，需要在它的终端先按 Control + C。

## 2. 使用你已有的 Riot Key 和普通对局

1. 在研究台右上角点击「Riot 数据控制台」。
2. 已有数据时，选择原来的 `data` 文件夹；新用户保持默认即可。后台有任务时不能切换目录。
3. 在 API Key 输入框填写你的 Key，保存并验证。Key 留在本机，不进入代码提交。
4. 按旧控制台的提示填写「名字#标签」或 PUUID，同步少量普通比赛；已有比赛可跳过本步骤。
5. 点击「进入比赛研究台」，再点击「导入现有普通对局」。等到顶部出现完成提示。
6. 点击比赛右侧「查看」。拖动观察时刻滑块，查看十名选手的经济、经验、等级、补刀；切换曲线指标查看资源差。展开质量报告核对异常。

只存在数据库里的旧数据，如无法自动列出，可先在旧控制台按 Match ID 补下载完整详情与时间线。研究台不会把职业选手的排位赛归为 LPL。没有数据时显示空状态，不自动生成假比赛。

## 3. 真实职业比赛文件导入

此部分需要来源方提供真实数据，**不是让你自己编造 JSON**。把本段交给提供数据的人即可。当前标准化适配器是 Match-V5；其他职业数据格式必须先开发专用适配器，原始响应本身仍可通过 `Warehouse.capture` 存档。

复制 [导入清单示例](../examples/import.example.json)，保存为 `import.json`。在它旁边放置完整 `match.json`、`timeline.json`。修改来源名与每局 context：赛事、赛季、BO3/BO5 系列赛 ID、局数、开赛时间、蓝红方稳定战队 ID 及名称、来源 ID 对照证据。正式样本将 `synthetic` 设为 false；仅改标记不能证明真实性，仍需来源和人工核验。

研究台展开「从已授权的文件或赛程来源导入」，填 `import.json` 的完整路径，点击「导入比赛文件」。不知道完整路径时，在 Finder 选中文件，按 `Option + Command + C` 复制路径，再粘贴到输入框。导入失败会保留已经获取的原始内容，任务日志显示失败条目；修复文件后重新导入。

也可以在仓库目录执行：

```bash
python3 -m lolab --data ./data research import "/完整路径/import.json"
python3 -m lolab --data ./data research rebuild
```

第一条导入本地文件；第二条只读本机存档重建全部派生比赛，不联网。相同处理版本、相同来源记录和相同修正集的重建不会重复添加派生版本；重复导入会保留新的观察记录，但相同数据体只压缩存储一份。

## 4. 人工修正

比赛详情中展开「人工修正与历史」。从质量报告复制字段路径，例如 `/timeline/info/frames/15/participantFrames/1/totalGold`。这表示第 16 个采样帧（编号从 0 开始）中 1 号选手的总金币；**帧编号并不保证等于比赛分钟数，先核对时间戳**。

填写当前值、正确值、操作者及证据理由。数值直接输入 `1500`；缺失值用 `null`；字符串要带双引号，例如 `"16.1.1"`。点击「记录修正并重新计算」，检查新质量报告和修正历史。当前值与实际不符时会拒绝覆盖。要撤回修正，再添加一次反向修正并写清原因，不能删除审计历史。

当前只允许版本、时长、帧时间、选手数值/位置、部分事件身份和资源字段、比赛状态修正。不能从页面修改来源权限、LPL 标签、胜负标签或原始响应。重新获取的数据与历史修正冲突时必须人工处理，不能自动套用旧修正。

## 5. LPL 赛程与十局验收

「运行 LPL 验收」在目前没有真实样本时显示未通过，这是正常结果。至少十**局**完整比赛，通过身份对照、状态字段、位置、装备事件和质量检查后，还必须核实稳定发现能力、历史可追溯范围、限速以及长期保存/模型分析权限。报告另列 BO3/BO5 系列赛数；十局不等于十个系列赛。验收报告是当时的快照，新增或修正数据后需重跑。

Riot Key 不可填作 PandaScore token。可选赛程发现适配器需要 PandaScore 账号提供的 token，和从其官方接口核实的 LPL leagueId；不默认猜一个 ID。拿到权限后，复制 [赛程配置](../examples/discovery.example.json)，填写 leagueId。token 通过本机终端环境变量 `PANDASCORE_TOKEN` 提供，不放配置文件；不要公开它。可请技术协助在本机配置。然后执行：

```bash
python3 -m lolab --data ./data research discover "/完整路径/discovery.json"
python3 -m lolab --data ./data research discover "/完整路径/discovery.json" --watch 900
```

第二条在此终端保持运行，每 15 分钟发现一次；关闭终端或按 Control + C 就停止，不会安装隐藏定时任务。中断后重新运行保留分页断点；完成整轮后下一轮从第一页重新检查，以发现赛程修订。赛程里的 games ID 只属于 PandaScore，不能直接拿到 Riot 接口请求，也不能自动与蓝红双方对齐。

核验来源和权限的人填写 [验收声明示例](../examples/attestation.example.json)，然后执行：

```bash
python3 -m lolab --data ./data research audit --attestation "/完整路径/attestation.json" --out lpl-audit.json
```

没有真实证据不要填写 approved。即使技术检查通过，人工填入的声明也不是系统自动验证的授权证明。网页简单验收不自动重用旧权限声明，正式报告用上面的命令附具名核验证据。

## 6. 分析、训练边界与备份

历史领先转化率只表示样本中领先方后来赢了多少次，不是训练后的实时胜率。不同时间点使用该时刻及之前最近一帧，缺失或过旧的帧不补零、不看未来；局数较少时结果可能很不稳定。研究台按完整版本号、赛事和类型分开统计。

开发者可导出独立标签和固定时点特征，并用含时区的日期划分训练测试集，跨边界的整个 BO3/BO5 放测试集：

```bash
python3 -m lolab --data ./data research features --cutoff 2026-07-01T00:00:00Z --minute 15 --out features.json
```

当前没有训练模型，也没有因果决策评价。特征导出不是模型已验证。静态装备价格不匹配比赛版本时保持未知，不使用最新版价格填充历史对局。

所有研究数据保存在当前 data 目录的 `research/warehouse.sqlite3`。备份最简单方法：先按 Control + C 停止所有使用此 data 目录的服务/导入命令，再复制整个 `data/research` 文件夹。运行中的数据库可能还有 `-wal` 和 `-shm`，不要只复制主文件；在线备份应使用 SQLite backup API。触发器能防止程序误改历史，但不能防止磁盘所有者删除整个数据库，仍需备份。旧 JSON 和旧项目数据库均不被迁移操作改写。
