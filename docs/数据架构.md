# 数据架构与开发契约

Python 3.10+ 标准库；本机 HTTP 服务仅监听 127.0.0.1。新仓库为 `data/research/warehouse.sqlite3`，使用 WAL 和参数化 SQL。旧 JSON/SQLite 只读导入，旧 ZIP 项目不变。

## 层次与重建

| 层 | 存储 | 语义 |
| --- | --- | --- |
| 原始响应 | `blobs` + `responses` | gzip 原始 body、SHA-256、来源/接口版本/请求时间/状态；重复请求各记一条，重复 body 共享内容 |
| 来源 ID 对照 | `mappings` | `(source, source_id)` 唯一对应 gameId，冲突拒绝；证据一并保留 |
| 标准比赛/状态/事件 | `revisions.document` | schemaVersion、pipelineVersion、context、meta、participants、draft、frames、events、labels、quality、provenance、revision |
| 特征 | `research features --out` | 显式白名单差值、观测时间、patch、来源 revision；标签独立，附整场切分 |
| 模型与预测 | 尚无 | 没有模型即空列表；不返回伪造 0%/50% 胜率 |
| 人工修正 | `corrections` | author/reason/created_at/path/expected/value；按顺序应用于内存副本，重建下游 |
| 数据源验收 | `audits` | 技术检查与具名来源/权限声明快照；不足十局或缺权限证据为 blocked |
| 工作记录 | `jobs`, `checkpoints`, `source_limits` | 可更新的运行状态、失败次数、恢复页、跨请求/重启限流等待 |
| 赛程视图 | `fixtures` | 可更新的来源赛程最新状态，每条链接到不可改写的 response |

`blobs/responses/mappings/revisions/corrections/audits` 有禁止 UPDATE/DELETE 的触发器。此机制用于程序防误写，不是 WORM 硬件或防管理员篡改。SHA 在读取时重算校验。在线备份需 SQLite backup API；离线可完整复制 research 目录。

HTTP 获取在解码之前保存完整响应字节，包括失败响应；不保存 API Key、Authorization、cookie 请求头。地址中的认证查询参数脱敏，仅保留内容类型等安全响应头。离线文件导入记录 fidelity=file-bytes；兼容旧 Python dict 调用时为 reserialized-json，不能声称它与最初网络传输的空格/字节完全一致。原始记录归档后，未知新增字段不会丢失。

网络最多每轮四次尝试；429 遵守 Retry-After 秒数或 HTTP 日期，长等待保存断点并退出，不截短上游要求。来源级保守间隔默认 1.3 秒，跨 Client 和进程保存；真实服务配额还须按账号实测。401/403/404 不无限重试。Riot 新下载路径使用请求头认证；旧认证诊断/旧无 data_dir 调用保持兼容，但研究数据采集不将 Key 放入 URL。TLS 校验保持开启，禁止带凭证自动跳转到其他域。

## 标准结构

- `context`：gameId、kind（competitive/soloqueue/unclassified）、synthetic、league、season、stage、seriesId、gameNumber、startTime（含时区）、status、teams（100/200 对应来源稳定战队 ID）、mappingEvidence。未知留空，不从选手名字猜职业身份。一个 seriesId 表示 BO3/BO5 对阵，和提供方名为 serie 的赛季概念不同。
- `meta`：原始比赛 ID、gameVersion、queueId、platformId、时长、采样间隔。最终胜负仅在 `labels.blueWin`。
- `participants`：participantId 1–10、puuid、teamId、英雄 ID/名、选手名、角色。角色可能是赛后推断，因此不进入当前导出特征。
- `frames`：timestampMs、十人观测、两队合计、差值、recentEvents、cumulativeComplete。采样粒度沿用来源，不插值或伪造每秒状态。没有可靠十人观测时队伍合计为 null。
- `events`：所有可定位到有效帧之前的、去重后的事件，保留额外字段。时间超出最终帧/无效时间的事件仍在 raw，质量报告指出异常。完全相同的事件指纹只算一次，同时警告；若来源允许相同时间重复合法事件，需增加来源 event ID 策略再投产。
- `draft.bans` 保存来源 ban 列表；阵容选人来自 participants。未实现阵容协同打分、团战自动划分。

资源分开：小龙、远古龙、大龙、先锋、虚空幼虫、厄塔汗；未知 monsterType 阻止质量通过。截断或缺失事件数组之后，累计资源/击杀/装备记为未知；不把不完整计数当 0。版本全号参与分组；机制改动需修改适配规则及 pipelineVersion、离线重建，不能只重训旧特征。

## 质量、修正及防泄漏

检查缺失、无效数值、时间顺序/间隔/首尾覆盖、十人身份、队伍、胜负互补、总金币/经验/等级/补刀下降、当前金币大于总金币、最终比分与资源/选手统计矛盾、未知资源及已知异常比赛标记。最终统计只在来源提供相应字段时比对；质量通过不等于所有可想象的异常都被排除。

修正仅在白名单路径上替换单个字段，不删历史，不添加虚假事件；expected 作乐观锁，冲突拒绝。规范化/质量/统计每次从 raw + corrections 重算，revision 记录原始响应 ID、哈希与修正 ID。修正失败不会触碰 raw。

特征只能选 `timestamp <= target` 的最近一帧，超过 1.5 个采样间隔不使用；不取“距离最近”而读到未来。只导出预定义差值，不包含事件文本、GAME_END winner、最终装备/最终比分或赛后位置。整系列赛跨切分边界时全放测试集，禁止分钟行随机切分。该基础检查不替代后续完整训练数据审查。

## 本机接口

GET `/api/research/status`、`/api/research/games?league=&kind=&season=&patch=&team=&player=`、`/api/research/game?id=`、`/api/research/stats`。

POST `/api/research/action`，JSON action=migrate/import/rebuild/audit/discover（文件类操作附 path）；POST `/api/research/correct`，JSON gameId/patch/author/reason。长任务复用 `/api/job`；服务只允许一个后台导入/修正任务。POST 要求同源 application/json，校验本机 Host/Origin，拒绝跨站网页调用。

目前 games/stats 将所选游戏载入内存，适用于本地初期验证；万局规模需要新增摘要索引/分页及离线统计聚合，不能仅因压缩存档可容纳万局就宣称界面已通过该规模性能验证。
